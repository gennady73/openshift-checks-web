How to Write Custom Scripts

The Editor allows you to write custom Bash scripts to check specific characteristics of your OpenShift cluster. These scripts run securely using the oc command-line client and report their results back to the application.

Required Script Structure

Every custom script must follow a specific structure to interact correctly with the underlying framework:

  1. Shebang: Always start your script with #!/usr/bin/env bash.
  2. Metadata: You must provide a description using the # description: format.[1] This text is parsed by the engine and automatically populates the "Description" column in the UI tables.
  3. Utilities: Source the framework's utility file to access standard environment variables and output functions (like the msg command).
  4. Cluster Logic: Write your oc commands to evaluate the cluster state. Ensure you handle potential permission errors gracefully.
  5. Exit Codes: Exit the script using the framework's standardized state variables so the UI knows which color-coded badge to assign.

Standard Exit Codes

The framework interprets the exit code of your script to determine the final status badge shown on the Home and Diff pages:[[2]]

exit ${OCINFO} Generates a blue INFO or green PASS badge. Use this when the check completes successfully.
exit 2 Generates a red FAIL badge. Use this when the check identifies a critical degradation or error.
exit ${OCSKIP} Generates a gray SKIPPED badge. Use this if the cluster doesn't have the required permissions or operators installed to run the check.
exit ${OCUNKNOWN} Generates a yellow UNKNOWN badge. Use this as a fallback if the script encounters an unhandled state.

Example Script

Here is a basic example of a valid custom script that counts the number of running pods in the cluster, utilizing the required utility sources and output formatting:

#!/usr/bin/env bash

# description: Show the pods running in the cluster

# 1. Source the utility file for helper functions
 && source $(echo "$(dirname ${0})/../utils")

# 2. Perform your logic and check permissions
if oc auth can-i get pods -A >/dev/null 2>&1; then
    # 3. Output a message to the UI using the 'msg' function
    msg "Total pods: $(oc get pods -A --no-headers | wc -l)"

    # 4. Exit with the appropriate success state
    exit ${OCINFO}
else
    msg "Couldn't get pods, check permissions"
    exit ${OCSKIP}
fi

# Fallback exit state
exit ${OCUNKNOWN}
